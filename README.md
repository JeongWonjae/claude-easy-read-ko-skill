# easy-read-ko

AI가 쓴 한글 글을 쭉 읽히게 고쳐 주는 Claude Code 스킬입니다.

AI가 쓴 한글 설명은 내용이 맞아도 읽기 힘들 때가 많습니다. 한 문장에 절이 서너 개씩 이어지고, 명사가 조사 없이 뭉쳐 있고, 결론이 문단 끝에 숨어 있기 때문입니다. 이 스킬은 그런 문장 구조를 패턴으로 찾아 고칩니다. 내용은 바꾸지 않습니다.

## 전후 비교

고치기 전:

> 해결 방안으로는 프로젝트 단위 정책 예외 설정을 통한 협력사 도메인 허용, 또는 정책을 유지한 채 그룹/서비스 계정 기반의 우회 경로 안내 두 가지가 있으며, 전자의 경우 협력사 측 고객 ID 확인이 선행되어야 하고 보안 통제 변경에 해당하므로 승인이 필요합니다.

고친 뒤:

> 해결 방법은 두 가지입니다. 첫째, 이 프로젝트에만 정책 예외를 걸어 협력사 도메인을 허용합니다. 그러려면 먼저 협력사의 고객 ID를 확인해야 합니다. 보안 통제를 바꾸는 일이라 승인도 필요합니다.

## 동작 방식

스킬은 세 단계로 동작합니다.

1. **진단**: 글을 문장 단위로 읽으며 읽기 힘든 패턴을 찾습니다. 판정은 글자 수와 개수 같은 기준으로 합니다.
2. **고쳐 쓰기**: 패턴마다 정해진 처방을 적용합니다. 숫자, 경로, 명령어, 고유명사는 그대로 둡니다.
3. **자가 점검**: 고친 글을 다시 진단합니다. 원문과 비교해 사실이나 조건이 빠지지 않았는지 확인합니다.

찾는 패턴은 여섯 가지입니다.

| 패턴 | 판정 기준 | 처방 |
|---|---|---|
| 긴 문장 | 60자를 넘거나 이어 붙인 절이 3개 이상 | 한 문장에 한 사실만 남기고 나눈다 |
| 명사 뭉치 | 명사가 조사 없이 4개 이상 이어짐 | 조사와 동사를 넣어 풀어 쓴다 |
| 번역투와 수동태 | "~에 의해", "~를 통해 ~를 수행" | 행위자를 주어로 세운다 |
| 핵심이 뒤에 있음 | 결론이나 요청이 문단 끝에 있음 | 결론을 첫 문장으로 올린다 |
| 끊기는 흐름 | 한 문장에 괄호, 슬래시, 화살표가 2개 이상 | 별도 문장으로 빼거나 말로 푼다 |
| 정의 없는 용어 | 약어나 별칭이 설명 없이 나옴 | 처음 나올 때 풀어 쓴다 |

패턴별 전후 예시는 [`easy-read-ko/patterns.md`](easy-read-ko/patterns.md)에 있습니다.

## 설치

`easy-read-ko` 폴더를 Claude Code의 스킬 폴더에 복사합니다.

```bash
git clone https://github.com/JeongWonjae/claude-easy-read-ko-skill.git
cp -r claude-easy-read-ko-skill/easy-read-ko ~/.claude/skills/
```

새 세션을 열면 스킬 목록에 `easy-read-ko`가 보입니다.

## 사용

고칠 글을 붙이거나 파일을 가리키고 이렇게 말합니다.

- "가독성 다듬어줘"
- "읽기 쉽게 고쳐줘"
- `/easy-read-ko`

## 평소 답변에도 적용하기

스킬은 부를 때만 동작합니다. 평소 답변도 이렇게 쓰게 하려면 `~/.claude/CLAUDE.md`에 아래 규칙을 넣습니다.

```markdown
### 한글 문장 가독성 규칙
- 한 문장에는 한 사실만 쓴다. 60자를 넘기면 나눈다.
- 결론이나 요청을 문단 첫 문장에 둔다.
- 명사를 조사 없이 잇지 않고 동사로 풀어 쓴다. 문장은 서술어로 끝낸다.
- "~에 의해", "~를 통해 ~를 수행" 같은 번역투와 수동태를 쓰지 않는다.
- 괄호 속 내용은 별도 문장으로 뺀다. 선택지가 둘 이상이면 개수를 먼저 말하고 선택지마다 문단을 나눈다.
- 숫자, 경로, 명령어, 고유명사는 그대로 둔다. 가독성을 위해 사실이나 조건을 빼지 않는다.
```

## 내 글에 맞게 고치기

`patterns.md`의 예시와 기준은 출발점입니다. 읽기 힘들었던 문장을 만나면 그 문장을 `patterns.md`에 예시로 넣으세요. 새 유형이면 판정 기준과 처방을 붙여 새 패턴으로 추가합니다. 문장이 너무 잘게 끊긴다고 느끼면 60자 기준을 늘리면 됩니다.
