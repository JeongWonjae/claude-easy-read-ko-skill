# easy-read-ko: 한글 가독성 다듬기

한글 글을 **진단 → 고쳐 쓰기 → 자가 점검** 3단계로 다듬는다.
바꾸는 것은 문장 구조뿐이다. 사실, 숫자, 조건, 결론은 바꾸지 않는다.

패턴별 판정 기준과 전후 예시는 같은 폴더의 `patterns.md`에 있다. 작업 전에 반드시 읽는다.

## 입력

- 사용자가 붙여 준 글, 파일 경로, 또는 "방금 답변"처럼 대화 안의 글.
- 대상이 불분명하면 직전에 작성한 글을 대상으로 한다.

## 1단계. 진단

글을 문장 단위로 읽으며 `patterns.md`의 패턴에 해당하는 문장을 찾는다.
판정은 감이 아니라 `patterns.md`에 적힌 기준(글자 수, 개수)으로 한다.

- P1 긴 문장
- P2 명사 뭉치
- P3 번역투와 수동태
- P4 핵심이 뒤에 있음
- P5 끊기는 흐름
- P6 정의 없는 용어

진단 결과는 속으로만 정리한다. 사용자가 "어디가 문제였는지"를 물을 때만 보여 준다.

## 2단계. 고쳐 쓰기

패턴마다 `patterns.md`의 처방을 적용한다. 공통 원칙은 다음과 같다.

1. 한 문장에는 한 사실만 쓴다.
2. 결론을 문단의 첫 문장에 둔다.
3. 누가 무엇을 했는지 드러나게 능동태로 쓴다.
4. 괄호 속 내용은 별도 문장으로 빼거나 지운다.
5. 숫자, 경로, 명령어, 고유명사, 인용문은 한 글자도 바꾸지 않는다. 전문 용어와 약어는 지우지 않고, 처음 나올 때 한 번 풀어 쓴다.
6. 원문의 형식 규칙을 지킨다. 메일 초안이면 마크다운 기호를 쓰지 않는다.
7. 원문에 없는 내용을 더하지 않는다. 길이는 원문과 비슷하거나 짧게 한다.

이미 잘 읽히는 문장은 건드리지 않는다. 모든 문장을 고치는 것이 목표가 아니다.

## 3단계. 자가 점검

1. 고친 글에 1단계 진단을 한 번 더 돌린다. 남은 패턴이 있으면 다시 고친다. 최대 2회.
2. 원문과 나란히 놓고 사실, 숫자, 조건, 부정 표현("안 된다", "제외")이 빠지거나 바뀌지 않았는지 확인한다.
3. 의미가 달라질 위험이 있어 고치지 못한 문장은 그대로 두고, 결과 보고에 한 줄로 알린다.

## 출력

- 파일이 대상이면 같은 파일을 Edit로 고치고, 바뀐 곳만 짧게 알린다.
- 붙여 준 글이 대상이면 고친 글 전체를 보여 준다.
- 설명은 "무엇을 주로 고쳤는지" 한두 줄만 덧붙인다.

## 패턴 추가

사용자가 "이 문장도 읽기 힘들다"고 하면 그 문장을 `patterns.md`에 넣는다.
기존 패턴에 해당하면 예시로 추가하고, 새 유형이면 판정 기준과 처방을 붙여 새 패턴(P7~)으로 만든다.
